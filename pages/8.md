## 8 鸿蒙 PC 之我见：从移动设备到通用计算平台

回看最近的软件、系统折腾，鸿蒙其实已经具备了不少专业能力。浏览器能开 F12、装插件；HiShell、openEuler 甚至跨环境调用的 loh 都能用；第三方系统监控器可以读取 GPU 状态、电池功率和十几种传感器；FreeRDP 也有好几拨开发者在移植。这些进展都值得肯定。可另一方面，CapsLock/Esc 交换和触控板手势自定义找不到入口，截图软件无法识别窗口内部 UI 元素，HDR 播放器也不展示完整的解码渲染链路。连安卓兼容应用的资源占用都在任务管理器中隐身；硬件上那块优秀的压感触控板，似乎也还没有完全发挥出深度交互的潜力。

其中最有意思的反差，恰好来自 ClashBox。之前遇到 `invalid domain`，我能导出配置、追查 Mihomo 规则、翻源码找到问题，最后跑去 GitHub 反馈。一个小小的 bug，虽然折腾了半天，至少自己有办法查清楚、修好它，还可能顺手帮到其他用户。可是遇到系统层面的问题，情况就不一样了。想把键盘上的两个按键交换、自由映射触控板手势，反而无从下手。

由此我开始重新理解桌面操作系统。显然，系统开发者不可能事先想到所有人的使用习惯和需求。Windows、Linux 发展这么多年，积累下来的大量小工具和脚本，起点往往就是某个人觉得系统默认功能不顺手，自己动手补了一个。用户先要能观察和理解系统的行为（可观测性），才能决定如何调整（控制权）；现有功能不够，就通过公开接口开发工具（扩展权）；做好了还能分享出去，让更多人安装、维护、继续改进（分发权）。这几件事连起来，软件生态就有了持续生长的空间。哪怕官方暂时没有开发某项功能，也不必所有人一起干等着。

**我认为这正是鸿蒙 PC 目前的主要矛盾：移动操作系统延续下来的平台预设、统一管理的能力供给方式，与桌面通用计算不断产生新需求、需要用户自行探索和扩展的使用方式之间的矛盾。** 手机那套“官方喂什么你吃什么”的大家长逻辑搬到电脑上，连写个脚本、改改系统行为都处处受限就有点难绷了。

回望个人计算机操作系统的发展历史，早期 Windows、Mac OS、Linux 都首先扎根于传统桌面计算，后来逐渐适应电池供电的移动设备。2001 年，Windows XP 让消费级 Windows 正式转向已有的 NT 技术路线，Mac OS X 则以 Unix 技术底座取代经典 Mac OS。两者虽然技术路径不同，却都没有舍弃既有桌面计算生态。2012 年微软搞 Windows RT，把传统 Win32 桌面软件生态挡在门外，最后怎么暴死的，老玩家都见过。桌面系统一旦把底层权限锁死，就只剩个大号平板的壳了。

消费级鸿蒙 PC 恰好选择了另一条起步路线：它从移动鸿蒙生态出发，2025 年 5 月最初的产品是电池供电的笔记本与折叠屏电脑，截至 2026 年 10 月还没有类似 Mac mini、iMac 的消费级固定式台式机。这也反映了产品发展的重心。鸿蒙已经证明，移动设备的省电、安全、流畅和软硬件协同完全可以带进笔记本。我更想知道的是，长期稳定的后台运行、精细控制、底层可观测性和自主扩展能力，能否同样融入鸿蒙的设计哲学？

当然，开放得太随意，又容易重蹈 Windows 流氓软件横行的覆辙。交换键位、读取硬件状态、访问其他应用窗口、修改系统核心，风险显然各不相同，也没道理一股脑放开。鸿蒙完全可以坚持自己的应用沙箱、安全管理和软硬件协同路线，同时为高级需求提供公开稳定的接口、明确的权限说明、按需授权和撤销机制。默认体验继续保持简单安全，需要更多控制权的人也有正规渠道可走。甚至可以借此做出比传统桌面 OS 更完善的权限管理。

说到底，**一台 PC 的价值，不仅在于完成系统开发者预设的工作流，更在于允许用户创造出开发者从未想过的玩法。** 对于大多数消费者而言，鸿蒙 PC 已经逐渐具备成为一台优秀电脑的条件。但对从 Windows、Linux 迁移过来的 Geek User 而言，它还需要走完从「好用的桌面设备」到「真正属于用户的通用计算平台」的一段关键的路。软件数量可以随着开发者加入慢慢增长，功能缺失可以随着版本迭代逐渐补齐；但操作系统究竟愿意为用户自己的探索留下多少空间，恐怕从一开始就是一道更根本的选择题。
